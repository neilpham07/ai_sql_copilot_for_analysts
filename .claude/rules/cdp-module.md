# CDP Module — Finviet CDP Portal

## Mission

The CDP portal lets analysts build complex merchant segments using a visual rule-logic builder (AND/OR nested criteria groups), view real-time audience size estimates, and browse a pre-built BI segment library.

Target: Finviet's 100,000+ retail merchant network.

## Two-Tier AI Architecture

**Tier 1 — NLP → Structured Filter JSON** (Claude handles this):
- Input: free-form Vietnamese description of desired segment
- Output: valid JSON matching filter schema
- Claude maps intent to known field names from `CDP_CRITERIA_FIELDS`

**Tier 2 — Filter JSON → SQL** (deterministic Python, no Claude call):
- Input: structured filter JSON from Tier 1 or from the visual rule builder
- Output: valid PostgreSQL SQL
- `build_sql_from_filters()` handles this deterministically

This is safer than asking Claude to generate raw SQL from 200+ arbitrary field combinations.

## Filter Schema

```json
{
  "operator": "AND",
  "groups": [
    {
      "operator": "AND",
      "criteria": [
        {"field": "gmv_30d", "operator": "greater than", "value": 50000000},
        {"field": "app_last_active_days", "operator": "less than", "value": 30}
      ]
    }
  ]
}
```

Operators by field type:
- `numeric`: `"greater than"`, `"less than"`, `"between"`, `"equals"`
- `categorical`: `"is exactly"`, `"is not"`, `"is one of"`
- `boolean`: `"is exactly"` (values: `"Yes"`, `"No"`)
- `duration`: `"last consecutive"` (requires `"unit": "Months"`)

    where_clause = build_sql_from_filters(filters)
    return f"""

SELECT
    COUNT(DISTINCT m.id) AS audience_size,
    ROUND(100.0 * COUNT(DISTINCT m.id) / (SELECT COUNT(*) FROM merchants), 1) AS coverage_pct
FROM merchants m
LEFT JOIN transactions t ON t.merchant_id = m.id

## CDP Data Model (3 tables)

```sql
-- Segment registry
CREATE TABLE cdp_segment_metadata (
    segment_id        UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    segment_name      VARCHAR(255) NOT NULL,
    description       TEXT,
    filter_definition JSONB NOT NULL,        -- the filter JSON
    created_by        VARCHAR(100),
    created_at        TIMESTAMPTZ DEFAULT NOW(),
    updated_at        TIMESTAMPTZ DEFAULT NOW(),
    is_active         BOOLEAN DEFAULT TRUE,
    model_version     VARCHAR(50)            -- track which AI version generated it
);

-- Pipeline execution audit
CREATE TABLE cdp_segment_execution_log (
    log_id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    segment_id      UUID REFERENCES cdp_segment_metadata(segment_id),
    executed_at     TIMESTAMPTZ DEFAULT NOW(),
    execution_status VARCHAR(20),            -- success | failed | partial
    audience_count  INT,
    delta_count     INT,                     -- change vs. previous run (for anomaly alerts)
    execution_time_ms INT,
    error_message   TEXT
);

-- Merchant membership map
CREATE TABLE cdp_merchant_segment_map (
    merchant_id       BIGINT NOT NULL,
    segment_id        UUID NOT NULL REFERENCES cdp_segment_metadata(segment_id),
    added_at          TIMESTAMPTZ DEFAULT NOW(),
    probability_score FLOAT,                 -- ML score (0-1), nullable for rule-based
    PRIMARY KEY (merchant_id, segment_id)
);
CREATE INDEX idx_cdp_map_merchant ON cdp_merchant_segment_map(merchant_id);
```

Key decisions:
- **Upsert strategy** for membership refresh (not truncate+reload) to preserve audit trail
- `delta_count` enables Telegram alerting on anomalous segment size changes
- `probability_score` supports future ML model scores alongside binary SQL rules
